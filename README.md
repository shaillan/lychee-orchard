# 智慧果园管家 · 从田间到餐桌

面向赛道一「智慧果园管家」的可运行原型：**微信小程序（果农端）+ Web 管理看板 + 品质溯源**。

- 后端：Python FastAPI + SQLite（零配置，无需 MySQL/Redis）
- 果农端：微信小程序（原生 WXML，`miniprogram/`）
- 管理端：原生 HTML/CSS/JS + ECharts 看板（`frontend/`）
- AI 识别：任意 OpenAI 兼容的视觉大模型（默认智谱 GLM-4.1V-Thinking-Flash，免费；也可换千问 / 豆包 / 硅基流动），未配置 Key 时自动降级本地模拟，演示不中断
- 防治建议：本地农药/安全间隔期规则库生成，AI 不直出用药建议

## 四个通关点对应实现

| 赛道要求 | 实现 |
|---|---|
| 果园电子档案 | 地块分区 / 农事记录 / 用药台账 / 产量趋势（小程序「我的果园」+ 地块详情） |
| 病虫害拍照识别 | 拍照压缩上传 → 视觉大模型识别 → 规则库生成防治建议 + 安全间隔期校验；识别后可「按建议用药 / 人工清除 / 误判 / 忽略」→ 自动写台账并销项（处置闭环）；判为误判时可回填真实类别，形成可导出的纠错样本；识别记录页可回看并补处置 |
| 品质溯源 | 一物一码（批次码 + 二维码），扫码展示「种植—管护—销售」三段式 + 哈希存证链；可打印批次质量合格证 |
| 农事数据看板 | 产量趋势 / 用药堆叠 / 虫害周趋势 / 虫害热力图 + 安全间隔期拦截警示 + 用药合规明细表（可导出 CSV） |

## 接入真实 AI 识别

后端调用的是 **OpenAI 兼容的 `chat/completions` 接口**，任何同类服务都能直接换，不用改代码。

**默认推荐：智谱 `glm-4.1v-thinking-flash`（免费）**

1. 在[智谱开放平台](https://open.bigmodel.cn/)手机号注册 → 「API Keys」创建密钥；
2. 复制 `.env.example` 为 `.env`，填写：

```bash
VISION_API_KEY=你的智谱Key
VISION_BASE_URL=https://open.bigmodel.cn/api/paas/v4/chat/completions
VISION_MODEL=glm-4.1v-thinking-flash
VISION_FALLBACK_MODEL=glm-4.6v-flash
VISION_PROVIDER=auto
```

> - `glm-4v-flash`（旧版）**不支持 base64 传图**，不能用；
> - `glm-4.6v-flash` 实测长期返回 `1305 该模型当前访问量过大`，所以默认用 `glm-4.1v-thinking-flash`，并把它配成备选；
> - 遇到 429/1305 会自动退避重试（1.5s、3s），仍失败才切换备选模型，最后才降级本地模拟。

3. 重启后端。识别结果会标注来源「云端 AI · zhipu:glm-4.1v-thinking-flash」；
   调用失败或未配置 Key 时自动降级为本地模拟，并在结果中标注「本地模拟」。

**换其它服务商**只改 `VISION_BASE_URL` / `VISION_MODEL`：

| 服务商 | `VISION_BASE_URL` | `VISION_MODEL` |
|---|---|---|
| 智谱（免费） | `https://open.bigmodel.cn/api/paas/v4/chat/completions` | `glm-4.1v-thinking-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | `qwen-vl-plus` |
| 火山豆包 | `https://ark.cn-beijing.volces.com/api/v3/chat/completions` | 你创建的推理接入点 ID |
| 硅基流动 | `https://api.siliconflow.cn/v1/chat/completions` | `Qwen/Qwen2.5-VL-7B-Instruct` |
| 本地 Ollama | `http://127.0.0.1:11434/v1/chat/completions` | `qwen2.5vl:7b` |

个别网关要求纯 base64（不带 `data:image/jpeg;base64,` 前缀）时，设 `VISION_IMAGE_FORMAT=raw`。

> 旧变量名 `DASHSCOPE_API_KEY` / `DASHSCOPE_BASE_URL` 仍然兼容，但推荐统一用 `VISION_*`。

> 识别输出被提示词约束在知识库的 21 个类别内（18 种常见病虫害：荔枝蒂蛀虫、荔枝蝽、荔枝霜疫霉病、荔枝炭疽病、荔枝瘿螨、荔枝尺蠖、荔枝煤烟病、荔枝藻斑病、荔枝叶瘿蚊、荔枝木虱、荔枝介壳虫、荔枝小灰蝶、荔枝酸腐病、荔枝龟背天牛、荔枝吸果夜蛾、荔枝蚜虫、荔枝蓟马、荔枝金龟子，另有健康叶片、健康果实、无法判断），
> 无法判断时返回「无法判断」并禁止给出用药建议。**用药建议始终由 `backend/rules.py` 规则库生成**。
>
> **四道防误报闸门**：
> ① 模型必须先写 `evidence`（看到的病斑形态）再给类别，没写出可辨识病征的病虫害结论会被后端降级为「无法判断」；
> ② 水珠、反光、果皮天然龟裂、未转色斑块明确不算病斑；
> ③ 置信度低于 65% 时只展示结果、不给自动处置建议，提示人工复核；
> ④ **二次确认**：病虫害结论会带着知识库的症状 / 危害部位 / 易混淆类别 / 鉴别要点再问一次模型，
> 模型答「图中没有该症状」时严格降级为「无法判断」（≤30%）；复核调用失败则保留首轮结论并标注「复核不可用」。
>
> 调用成本：健康 / 无法判断仍是 1 次调用；病虫害多 1 次（约 +2s），只复用首轮成功的模型、不重试、12s 超时。
> `VISION_CONFIRM=0` 可关闭二次确认，`VISION_CONFIRM_TIMEOUT` 调整复核超时。
>
> 知识库（`backend/rules.py` 的 `PESTS`）每个类别除症状 / 时机 / 备注外，还带
> `aliases`（别名，统一启发式归一）、`host_parts`（危害部位）、`differential`（易混淆类别 + 鉴别要点）、
> `non_chemical`（物理 / 农业防治措施）、`peak_months`（高发月份）、`monitoring`（监测要点）、
> `biological`（生物防治 / 天敌）。启动时 `validate_knowledge()` 自检字段完整性与交叉引用，只告警不阻断启动。
>
> 小程序端提供「病虫害知识库」浏览页（`pages/kb`）与详情页（`pages/kb-detail`），
> 支持关键词搜索（名称 / 别名 / 症状 / 防治时机 / 监测要点 / 鉴别）、虫害 / 病害筛选与「本月高发」筛选；
> 顶部按 `peak_months` 自动提示当季高发对象，详情页展示症状、高发期、监测要点、鉴别、非化学与生物防治及推荐药剂；
> `/api/pests` 与药剂清单会缓存到本地存储（`utils/kb.js`），断网时知识库仍可查询，并标注「离线缓存」。
> 首页快捷区、拍照识别页均可进入，识别结果也可一键跳转到对应条目。

## 评测与纠错回流

- **自建评测集**：图片放 `data/eval/images/`（也可用 `tools/fetch_eval_images.py` 从 iNaturalist /
  Bing 图搜自动抓一批候选图，生成核对页后再人工剔除）；`tools/prelabel.py` 先用当前识别链路批量打标，
  人工只需改正错的那几条；`tools/eval_vision.py` 输出 Top-1 准确率、分类别召回、混淆矩阵、
  低置信度占比与非目标图误报数，报告写入 `docs/eval-report.md`。
  评测直接调用 `ai_service.recognize()`，与线上识别完全同一条链路（含证据闸门与二次确认）。
  图片与 `labels.csv` 默认被 gitignore：自拍图无版权问题，网络图只做本地评测、不进提交材料。
- **纠错回流**：误判时界面会展开类别选择器，可把人工判定的真实类别一并提交
  （`POST /api/recognitions/{id}/handle` 的 `actual_class`，必须来自知识库）；
  `GET /api/recognitions/corrections` 可直接导出「模型判为 X → 实际为 Y」的样本，用于补评测集或微调。
  看板汇总 `recognition_corrected` / `recognition_correction_rate`。

## 台账留痕

- 农事记录与用药记录**不允许修改或删除**；录错只能作废（`POST /api/operations/{id}/void`、
  `POST /api/pesticide-records/{id}/void`），作废需填原因并记录操作人，原记录永久保留可查。
- 作废记录不再参与安全间隔期放行、合规明细 / CSV、看板统计与溯源展示，但地块档案里仍以「已作废」标记保留，
  形成可审计的更正轨迹。

## 一物一码

批次编码规则（参考 GS1 结构，自建规则）：

```
LZ / P03 / 20260702 / 0001
品种  地块   采收日期    包装序号
```

- 每个批次的二维码：`GET /api/batches/{batch_no}/qrcode`（PNG）；
- 小程序「批次二维码」页可直接展示、长按保存；溯源页也会展示批次二维码；
- 默认二维码内容为溯源码本身（小程序内「扫一扫」解析）；
  配置 `.env` 的 `QR_BASE_URL=https://your-domain` 后，二维码内容变为
  `{QR_BASE_URL}/trace?code=xxx`，消费者用微信扫码可直接打开 H5 溯源页。

### 哈希链校验（防篡改）

每次写入存证时，原文一并存入 `trace_hash_log.payload_json`：

- `record_hash = SHA-256(原文 + 上一条哈希)`，逐条首尾相连；
- 校验时按原文重算，任何一条被改动都会断链，并定位到具体记录 ID。

| 接口 | 说明 |
|---|---|
| `GET /api/trace/{code}` | 返回 `chain_verify`：`valid`、`total`、`tampered`、`broken`、`legacy` |
| `GET /api/trace-verify` | 全链校验结果 |

溯源页与小程序会在「哈希存证链」旁显示徽章：`✅ 链校验通过 · N 条` 或 `❌ 链校验失败 · 第 N 条`。

**现场演示**（工具会自动备份原值）：

```bash
python tools/hash_chain_demo.py tamper LZ-P03-20260702-0001
# 刷新 /trace?code=LZ-P03-20260702-0001 → 徽章变红并指出第几条
python tools/hash_chain_demo.py restore
# 刷新 → 恢复「链校验通过」
```

注意：单机哈希链只能证明「存证写入后未被修改」，不能证明录入时数据本身为真；更强证明需把链头对外锚定（印在合格证或第三方存证）。另外，当前链覆盖的是写入时的存证快照，直接改农事/用药业务表不会让链断——若要覆盖到业务明细，需要把明细一并写入存证并按批次对账。

### 批次质量合格证

溯源页（`/trace?code=...`）查询成功后，底部有「打印合格证 / 保存为 PDF」：

- 合格证独立于页面展示，打印时只输出这一页（A4 纵向），带批次二维码、产地、采收日期、农残检测、用药记录与安全间隔期状态、哈希链校验结果、签字栏；
- 被拦截的批次会印上红色「已拦截 · 不得销售」并附拦截原因，可直接打印给收购商看复核结果。

## 加分项

### 天气联动预警（免 Key）

`backend/weather.py` 调用 [Open-Meteo](https://open-meteo.com/) 未来 3 天预报（降雨量 / 降雨概率 / 逐小时湿度），
判断是否利于「荔枝霜疫霉病」发生；有风险时在 `/api/todos` 里追加一条预警待办，并附「雨前预防」建议。

- **界面设置地区**：H5「今日待办」和小程序「今日待办」顶部都有「天气地区」卡片，
  输入城市名（如「广州」）保存即可。后端用 Open-Meteo 地理编码换成经纬度，存入 SQLite `settings` 表，
  H5、小程序共用同一地区，保存后立即生效、重启不丢；未设置时仍用 `.env` 默认值。
- 区县名可能查不到（如「从化」），请输入上一级城市名（如「广州」）。
- 结果缓存 30 分钟、超时 3 秒、任何异常静默跳过——断网时只是少一条待办，不会拖慢接口；
  缓存按地区坐标分槽，切换地区后不会复用旧地区的结论。
- `.env` 中 `WEATHER_ENABLED=0` 可整体关闭（测试默认关闭）；`WEATHER_LAT` / `WEATHER_LON` / `WEATHER_LOCATION` 只是默认值；
- 接口：`GET /api/weather/region` 查看当前地区，`PUT /api/weather/region`（`{"name":"广州"}`）保存地区，
  `GET /api/weather/pest-risk` 查看风险。

### 采前：采收窗口 + 裂果预警（规则为主）

- **采收窗口**：按品种日历规则（妃子笑 6/5–6/25、桂味 6/20–7/10、糯米糍 6/28–7/18，未知品种回退 6/15–7/15）
  计算 `未到 / 临近 / 最佳 / 已过`，并给出当前物候期（花穗期 / 幼果期 / 果实膨大期 / 转色成熟期 / 采后）。
  `/api/plots` 与 `/api/plots/{id}` 每条地块新增 `maturity` 字段；地块页展示采收窗口卡。
- **拍照佐证**：`POST /api/plots/{id}/maturity-check` 把人工观察（成熟度评分 + 备注 + 照片）写入
  `farm_operations`（`operation_type="成熟度观察"`）。照片只作为证据回看，**不参与窗口判定**，避免识别误差带偏采收建议。
- **裂果预警**：久旱（过去 7 天累计 ≤5mm 且连续 ≥3 天无雨）→ 未来 3 天单日降雨达到品种阈值
  （糯米糍 8mm / 桂味 12mm / 妃子笑 20mm）→ 且处于果实膨大期或转色成熟期，才写入待办。
  天气取数复用 Open-Meteo（`past_days=7&forecast_days=3`），冷缓存直接跳过，**不会阻塞 `/api/todos`**。

### 采后：冷链倒计时 + 农残快检

- **冷链**：批次新增离树 / 预冷 / 发运 / 到货四个时间戳。`POST /api/batches/{batch_no}/cold-chain`
  按 `precool → ship → arrive` 顺序登记（顺序错误 400、重复 409、拦截批次 400），每次写入追加哈希存证。
  离树 >24 小时未预冷 → `/api/todos` 出现 `critical` 待办；`GET /api/batches`、`/api/trace/{code}` 均返回计算后的 `cold_chain`。
- **农残快检**：`POST /api/batches/{batch_no}/residue-tests` 录入机构、日期、结论（合格 / 不合格 / 待复检）、
  检测项与报告照片；`检测` 节点写入哈希链。**结论为「不合格」会把已放行批次改为 `blocked`**；
  「合格」不会自动放行被拦截批次（安全间隔期不可绕过）。
- **通用上传**：`POST /api/uploads`（JPG/PNG/WEBP）供检测报告、成熟度佐证复用。
- 溯源页（H5 与小程序）销售段新增「采后冷链」与「农残快检」区块；合格证增加冷链行与农残检测表格。
- 建批次时 `detection_report` 默认「待检测」，不再写死模板文案。

### 巡园报告 + 语音填报

- **连续巡园**：小程序识别页一次可选最多 9 张照片，逐张压缩上传（单张失败不中断），共享同一个 `patrol_id`；
  `GET /api/patrols/{patrol_id}` 聚合出「异常总数 / 按地块 / 按病虫害 / 重点地块 / 监测建议」。
  接口不可用时前端本地聚合兜底。健康叶片与健康果实不计入异常。
- **语音填报**：小程序填报页接入微信同声传译插件（`WechatSI`），备注可语音转文字后追加；
  开发者工具 / 游客 AppID 无插件时按钮隐藏并提示手动输入，不影响提交流程。

> **启用语音的前置条件**（重要）：插件必须先在 [mp.weixin.qq.com](https://mp.weixin.qq.com) 对应 AppID 的
> 「设置 → 第三方设置 → 插件管理」中添加「微信同声传译」。未授权时声明插件会让**微信开发者工具的模拟器直接启动失败**
> （日志报 `插件未授权使用, user uin can not visit app`），所以本项目默认不在 `app.json` 里声明插件。
>
> 注意：**小程序测试号（测试号管理页）没有「插件管理」入口，无法使用任何插件**。要在测试号上开发，
> 请保持 `app.json` 不声明插件（当前默认状态）；需要演示语音，改用注册的正式小程序 AppID。
>
> 授权完成后，在 `app.json` 顶层加回下面这段即可，表单页会自动点亮麦克风按钮：
>
> ```json
> "plugins": {
>   "WechatSI": { "version": "0.3.5", "provider": "wx069ba97219f66d99" }
> }
> ```

### 识别记录页

## 关键设计决策

1. **识别只给类别，用药走规则库**：AI 结果不直接变成用药建议，避免超范围用药；临近采收自动过滤长间隔期药剂。
   识别后必须落处置（用药 / 人工清除 / 误判 / 忽略），用药处置复用台账校验并回链识别，待办销项——形成「识别→处置→销项」闭环。
   系统还会按「风险等级 + 距采收天数 + 合规药剂」给出**建议处置及理由**并高亮对应按钮，果农确认或改选，避免让用户自己判断。
2. **安全间隔期自动驱动放行**：批次创建时校验该地块全部用药记录，未过间隔期的批次状态为 `blocked`，不生成销售溯源码。
3. **哈希链存证**：批次关键节点（种植/管护/销售）写入追加式哈希日志，每条携带上一条哈希；原文一并入库，校验时逐条重算，改任一条即断链并可定位到记录 ID。
4. **能砍则砍**：不引入时序库、消息队列、区块链；单库 + 单进程即可完整演示。

## 常见问题

- **小程序请求失败**：确认后端已启动、`utils/config.js` 地址正确，并在开发者工具关闭域名校验。
- **识别显示「本地模拟」**：未配置 `VISION_API_KEY` 或云端调用失败，检查 `.env` 后重启；后端日志里会有降级原因（如 `mock_fallback(HTTPStatusError)`）。
- **天气地区保存失败**：地理编码查不到区县名时，输入上一级城市名（如「从化」→「广州」）；提示 502 说明 Open-Meteo 暂时不可用，稍后再试，已保存的地区不受影响。
- **云端返回 400 / 1210**：优先检查模型是否支持 base64 传图（`glm-4v-flash` 不支持，用 `glm-4.1v-thinking-flash`），以及 `VISION_BASE_URL` 是否为 OpenAI 兼容端点。
- **病虫害结论变成「无法判断」**：可能触发了二次确认——模型在复核时认为图中没有该症状。请重新拍摄清晰、对焦病斑的照片，或人工复核；界面会标注「二次确认：未通过，已降级」。若复核调用本身失败，会保留首轮结论并标注「复核不可用」。
- **给 `.env` 设置 `VISION_CONFIRM=0`** 可关闭二次确认，回到单次调用。
- **二维码在手机上打不开 H5**：默认二维码内容是溯源码本身；需要 H5 链接时配置 `QR_BASE_URL`，且该域名需公网可访问。
